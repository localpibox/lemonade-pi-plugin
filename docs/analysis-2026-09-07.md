## Part 3 — Research: machine-readable sources for vendor sampling params

**No single universal source exists.** Ranked for local-GGUF use:

| Source | Coverage | Format | Notes |
|---|---|---|---|
| **GGUF `general.sampling.*` kvs** (llama.cpp PR #17120, merged 2025-11-25) | Models converted after the merge; unsloth's newer packs have them | Binary header, parseable from first ~1MB | **Best tier**: checkpoint-exact, offline-capable, no auth. Verified on our own Q4_K_XL file (below). Field-poor: no penalties, no thinking/non-thinking split. Older GGUFs lack them. |
| Quant-repo README "Sampling Parameters" block (unsloth etc.) | Newer families; missing in older repos (gemma-3) | Markdown, regex-parseable, public/no auth | Has per-mode splits + all 6 fields. Format varies per packager — parser must be lenient. |
| Official HF card README | All families (SoT) | Markdown; **Gemma gated → needs HF token** | Fallback tier. |
| HF `generation_config.json` (`/resolve/main/…`) | Widely present | Clean JSON | Field-poor (temp/top_k/top_p only); can lag the card (Qwen3-235B file 0.6 vs card 1.0 thinking). Presence checkable without auth via `/api/models/<id>` siblings. |
| OpenRouter / litellm / HF Inference Recommender | hosted-only / pricing-only | JSON | Useless for local GGUF (mostly null defaults for our exact models). |

**Key insight: params are per-CHECKPOINT, not per-family** (Qwen3-2507 thinking temp 0.6 vs Qwen3.8-27B thinking temp 1.0). Family tables are an anti-pattern.

### GGUF format — verified facts

- **GGUF v3 layout** (from llama.cpp `gguf-py/gguf/gguf_reader.py`):
  `magic u32 | version u32 | tensor_count u64 | kv_count u64`, then per KV:
  **`key_len u64 | key bytes | type u32 | value`** (keys are u64-length-prefixed — NOT plain zstr; this is why naive parsing misaligns).
- Type enum: `0=uint8 1=int8 2=uint16 3=int16 4=uint32 5=int32 6=f32 7=bool 8=str 9=array 10=u64 11=i64 12=f64`.
- PR #17120: `convert_hf_to_gguf.py` auto-embeds `generation_config.json` into `general.sampling.*`; llama.cpp applies embedded values at load unless CLI flags override (priority: user flags > embedded > defaults). Kvs introduced: temp, top_k, top_p, min_p, xtc_*, penalty_last_n, penalty_repeat, mirostat_*.
- **Live-verified** on `unsloth/Qwen3.8-27B-GGUF:Qwen3.8-27B-UD-Q4_K_XL.gguf` (200KB range-request):
  ```
  general.architecture = qwen35
  general.sampling.temp  = 1.0
  general.sampling.top_p = 0.95
  general.sampling.top_k = 20
  general.base_model.0.repo_url = https://huggingface.co/Qwen/Qwen3.8-27B   ← official repo pointer for free
  ```
  Matches current catalog values exactly → validates the seed data with a machine-readable source.
- Lemonade `/v1/models` returns `checkpoint: "unsloth/<Repo>:<file>.gguf"` — the exact pointer needed to range-request the file from HF. Lemonade exposes zero sampling fields itself and no `/props`.

## Part 4 — Plan

### Phase A — Param resolver (replaces family tables)

1. **`lib/gguf-params.ts`** — GGUF v3 header parser (~40 lines, port of the verified Python): range-request first ~1MB from `https://huggingface.co/<repo>/resolve/main/<file>` using Lemonade's checkpoint pointer; walk KV table (stop cleanly at arrays/truncation); return `{ sampling: {temp?, top_p?, top_k?, min_p?}, architecture?, baseModelRepo? }`.
2. **`lib/param-sources.ts`** — tiered resolver:
   - Tier 1: GGUF kvs (checkpoint-exact; wins conflicts)
   - Tier 2: quant-repo README "Sampling Parameters" block (fills penalties + thinking/non-thinking split); official repo via `base_model.*.repo_url` when available, else org-card fallback (optional `LPB_HF_TOKEN` for gated repos)
   - Tier 3: manual entry (always available in UI)
   - Merge rule: GGUF wins on overlap, README fills gaps; every field carries provenance.
3. **Delete** `suggestFamily()` from `lib/model-probe.ts`; probes write ONLY what they proved (`reasoning`, `vision`). Sampling/ceiling become explicit, confirmed suggestions in the UI.
4. **`_meta` block per entry** (ignored by tuning engine, rendered by UI): `{ probedAt, probe: {thinking, vision}, paramsSource: [{field, source, ref}] }`.
